## 0. 先明确这个平台要干什么（买错的地方都在这）

目标链路：

```
心率胸带/手环（BLE 标准心率服务 0x180D / 特征 0x2A37）
      │  ①
      ▼
ESP32-S3 网关（BLE 主机 + WiFi，固件在 hardware/esp32_hr_bridge/）
      │  ② HTTP POST /api/device/health-data（带 X-Device-Token）
      ▼
后端（Spring Boot）→ MySQL → App 实时监控页 / 预警
```

**已经有的、不用再买**：

| 已有 | 说明 |
|---|---|
| 一块 PCBA（ESP32-S3-WROOM-1 + CP2102N） | 就是你给我看的那块（3 相逆变器板）；USB 串口驱动**已装好**（`silabser.inf` v10.1.8.2466） |
| 一块能对外暴露 0x180D 的手环 | 你之前用 nRF Connect 确认过，可以直接用 |
| 电脑 + 安卓手机 | 编译、烧写、联调都在电脑上；手机已能连本机后端 |
| 血压计（拍过 60 张照片的那几台） | OCR 的真值来源 |

**三条会买错的硬约束**（详见第 5 节）：

1. **心率源必须对外暴露标准 BLE 心率服务**。市面上大部分手环（小米、华为、荣耀…）是**封闭协议**，第三方连上拿不到 0x2A37 —— 买了也用不了。
2. **USB 线要能传数据**，不能是"只能充电"的线（这次就卡在这上面）。
3. **USB-TTL 优先买 CP2102 芯**（驱动本机已装好）；买 CH340 还要再装一遍驱动。

## 5. 采购时的坑（都是已经踩过的）

1. **手环大多不对外暴露 0x180D**
   小米/华为/荣耀等封闭生态，第三方 App 连上读不到标准心率特征。
   要么用你已验证过的那块，要么直接买**胸带**（Magene H803、CooSpo H808S、Polar H10 都行）。
   买之前用 nRF Connect 扫一下，能看到 `Heart Rate Service 0x180D` 才买。

2. **"USB 线"要能传数据**
   这次板子插上后电脑完全看不到设备，第一嫌疑就是充电线（或 USB 口只供电）。
   买线时认"数据线"，或者直接用你平时给手机传文件那根。

3. **USB-TTL 认准 CP2102 芯**
   本机已装好 CP2102 的官方驱动（`silabser.inf` v10.1.8.2466）。
   买 CH340 就要再走一遍驱动安装（而且这个网络下 Silabs 官网和微软的 catalog CDN 都不可达，
   只能靠 Windows Update 装 —— 能装但折腾）。

4. **ESP32-S3 板子不需要 PSRAM**
   固件目前 RAM 用 15.8%、Flash 用 32.5%，**N8（8MB）足够**，N16R8 也行但没必要加钱。

5. **别用你手上那块 3 相逆变器 PCBA 当长期网关**
   它的供电设计是给电机驱动的（很可能 12/24V 输入），拿它当 5V 网关属于降级使用。
   留着它做它该做的事，网关用标准开发板。

6. **血压计型号一定要记下来**
   OCR 的准确率高度依赖机型字体与屏幕布局（现有模型只在你那 60 张上验证过）。
   换机型必须重新验，记录型号才能判断"是模型不行"还是"这一台不行"。

## 7. 需要你确认的两件事（影响要不要买第 5、10 项）

1. **你那块 PCBA 的供电输入是什么？**（看丝印/原理图：5V 还是 12/24V）
   —— 若只有 USB 5V 供电，那第 3 项直接用；若是 12/24V，长期测试需要对应电源。
2. **板子上有没有 2.54 排针引出 TX/RX/GND/IO0？**
   —— 有的话第 5、10 项可以省；没有且 USB 又只能供电，就必须买 USB-TTL。
