## 0. 先明确这个平台要干什么（买错的地方都在这）

目标链路：

```
心率胸带/手环（BLE 标准心率服务 0x180D / 特征 0x2A37）
      │  ①
      ▼
ESP32-S3 网关（BLE 主机 + WiFi，固件在 hardware/esp32_hr_bridge/）
      │  ② HTTP POST /api/device/health-data（带 X-Device-Token）
      ▼
后端（Spring Boot）→ MySQL → App 实时监控页 / 预警
```

**已经有的、不用再买**：

| 已有 | 说明 |
|---|---|
| 一块 PCBA（ESP32-S3-WROOM-1 + CP2102N） | 就是你给我看的那块（3 相逆变器板）；USB 串口驱动**已装好**（`silabser.inf` v10.1.8.2466） |
| **手环**（能对外暴露 0x180D） | 你已用 nRF Connect 确认过，可直接用 |
| **心率胸带** | ✅ 你已有 —— 长期测试首选它（戴上就有数据、摘掉就停） |
| **血压计**（拍过 60 张照片的） | ✅ 你已有 —— OCR 的真值来源 |
| 电脑 + 安卓手机 | 编译、烧写、联调都在电脑上；手机已能连本机后端 |

> 由于手环、胸带、血压计都已有：第 1 节的「心率胸带」、第 3 节的「第二块胸带」「血压计」
> **都不用买了**。按当前情况重算见第 9 节。

**三条会买错的硬约束**（详见第 5 节）：

1. **心率源必须对外暴露标准 BLE 心率服务**。市面上大部分手环（小米、华为、荣耀…）是**封闭协议**，第三方连上拿不到 0x2A37 —— 买了也用不了。
2. **USB 线要能传数据**，不能是"只能充电"的线（这次就卡在这上面）。
3. **USB-TTL 优先买 CP2102 芯**（驱动本机已装好）；买 CH340 还要再装一遍驱动。

## 5. 采购时的坑（都是已经踩过的）

1. **手环大多不对外暴露 0x180D**
   小米/华为/荣耀等封闭生态，第三方 App 连上读不到标准心率特征。
   要么用你已验证过的那块，要么直接买**胸带**（Magene H803、CooSpo H808S、Polar H10 都行）。
   买之前用 nRF Connect 扫一下，能看到 `Heart Rate Service 0x180D` 才买。

2. **"USB 线"要能传数据**
   这次板子插上后电脑完全看不到设备，第一嫌疑就是充电线（或 USB 口只供电）。
   买线时认"数据线"，或者直接用你平时给手机传文件那根。

3. **USB-TTL 认准 CP2102 芯**
   本机已装好 CP2102 的官方驱动（`silabser.inf` v10.1.8.2466）。
   买 CH340 就要再走一遍驱动安装（而且这个网络下 Silabs 官网和微软的 catalog CDN 都不可达，
   只能靠 Windows Update 装 —— 能装但折腾）。

4. **ESP32-S3 板子不需要 PSRAM**
   固件目前 RAM 用 15.8%、Flash 用 32.5%，**N8（8MB）足够**，N16R8 也行但没必要加钱。

5. **别用你手上那块 3 相逆变器 PCBA 当长期网关**
   它的供电设计是给电机驱动的（很可能 12/24V 输入），拿它当 5V 网关属于降级使用。
   留着它做它该做的事，网关用标准开发板。

6. **血压计型号一定要记下来**
   OCR 的准确率高度依赖机型字体与屏幕布局（现有模型只在你那 60 张上验证过）。
   换机型必须重新验，记录型号才能判断"是模型不行"还是"这一台不行"。

## 7. 需要你确认的两件事（影响要不要买第 5、10 项）

1. **你那块 PCBA 的供电输入是什么？**（看丝印/原理图：5V 还是 12/24V）
   —— 若只有 USB 5V 供电，那第 3 项直接用；若是 12/24V，长期测试需要对应电源。
2. **板子上有没有 2.54 排针引出 TX/RX/GND/IO0？**
   —— 有的话第 5、10 项可以省；没有且 USB 又只能供电，就必须买 USB-TTL。

## 10. 深入分析：还缺什么（按"它能解锁什么"排，而不是按价格排）

### 10.1 三个真缺口（不解决就会卡住，其余都是锦上添花）

**缺口一：网络 —— 这是当前唯一卡死"上报"这一半的硬障碍**
- 现状：家里 WiFi 是 **WPA2-Enterprise(802.1X)**，固件只支持 WPA2-PSK → 板子连不上。
- 换成改固件支持 802.1X 也不一定行：企业网常开**客户端隔离**（AP 之间不能互访），
  板子就算连上，也可能访问不到电脑的 8080。
- 用阿里云也不通：线上后端是**旧版本**，/api/device/bind 直接 403（没有设备接口）。
- **解法（对应购买项）**：买一个能自己发 **WPA2-PSK + NAT** 的小路由器/随身 WiFi。
  插在现有网络后面它自己开一个网：板子、手机、电脑都连它 →
  一次解决"只支持 PSK"、"客户端隔离"、"不用碰公司/房东网络"三件事。
  这是**目前性价比最高的一笔钱**。

**缺口二：供电稳定性 —— ESP32 同时开 BLE + WiFi 会瞬间拉大电流**
- 常见故障：板子随机重启 / BLE 连上就掉 / WiFi 一连就崩，而且**串口日志看起来完全正常**。
- 电脑 USB 口、劣质电源、长细线都会触发。这类问题**不用仪器排查非常费时间**。
- **解法（对应购买项）**：① 独立 5V/2A 电源；② 一个 **USB 电流表/功率计**（20–35 元）——
  插上就能看到电压跌落与瞬时电流，5 秒判断是"板子问题"还是"供电问题"。

**缺口三：取景稳定 —— OCR 的天花板不在算法，在拍照条件**
- 真机现在 8 张对 5 张；错的那几张多数是**反光/倾斜/手抖**，不是模型不行。
- **解法（对应购买项）**：俯拍支架 + 可调补光灯。这是唯一能直接抬真机识别率的硬件。

### 10.2 原清单漏掉的、值得加的（新增推荐）

| 新增项 | 价格 | 为什么值得 |
|---|---|---|
| **旅行路由器 / 随身 WiFi（能开 WPA2-PSK + NAT）** | 80–200 | 见缺口一。**建议优先买** |
| **USB 电流表/功率计** | 20–35 | 见缺口二。几十块钱换掉几小时的"玄学排查" |
| **带 IPEX 外置天线口的 ESP32-S3 板**（或另买 2.4G 小天线） | +0–30 | BLE 与 WiFi 共用 2.4G 射频，穿墙能力弱；网关要放到卧室/客厅时，外置天线比换路由器有用 |
| **12V/24V 直流电源**（**若**你那块 PCBA 需要） | 20–50 | 3 相逆变器板大概率是 12/24V 输入；没有合适电源的话它连上电都难 |

### 10.3 明确**不建议**买的（省钱 + 避免绕远路）

| 不买 | 原因 |
|---|---|
| **多买 2~3 块网关板** | 一个网关"只能连一个手环"是**固件限制**，不是硬件限制 —— platformio.ini 里本来就开了 CONFIG_BT_NIMBLE_MAX_CONNECTIONS=2。先把固件改成支持多连接（NimBLE 支持），一块板就能带 2 个手环，比买 3 块板划算 |
| 树莓派 / 小主机 | 后端跑在电脑或云上就够，不用再养一台机器 |
| 4G 模块 / 物联网卡 | 家里有网，先解决 PSK 问题；真要脱离网络环境再考虑随身 WiFi（上面那项已覆盖） |
| 更贵的开发板（N16R8、带 PSRAM） | 固件 RAM 只用 15.8%、Flash 32.5%，N8 足够 |
| 逻辑分析仪 / 示波器 | 当前没有需要逐位分析的信号问题；有 USB 电流表 + 串口日志足够定位 |
