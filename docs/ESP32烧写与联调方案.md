# ESP32 烧写与联调实施方案

> 目标：把手环心率桥固件烧进 **ESP32-S3-WROOM-1** 板子，让它常连手环采心率、
> 经 WiFi 上报到家庭健康中心后端，手机 App 里能看到数据与设备在线状态。
>
> 前置事实（已确认）：板子主控为 ESP32-S3-WROOM-1（原理图 OCR 得到），
> 手环暴露标准心率服务 **0x180D / 0x2A37**（用 nRF Connect 已验证可连接并读到心率）。

## 二、准备（约 20 分钟）

### 2.1 安装工具链（二选一）

**方案 A：PlatformIO（推荐，跨平台、依赖自动装）**

```bash
pip install -U platformio
pio --version          # 能打印版本即可
```

**方案 B：Arduino IDE**

1. 安装 Arduino IDE 2.x
2. 首选项 → 附加开发板管理器网址 填 `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
3. 开发板管理器搜 `esp32` 安装 **esp32 by Espressif**
4. 库管理器安装：**NimBLE-Arduino**（h2zero）、**ArduinoJson**（bblanchon）
5. 开发板选 `ESP32S3 Dev Module`，串口波特率监视器设 115200

### 2.2 硬件

| 项 | 要求 |
|---|---|
| 数据线 | **必须是能传数据的 USB 线**（只能充电的线会连不上；本项目调试手机时就踩过这个坑） |
| 供电 | USB 供电即可（BLE + WiFi 并发瞬时电流较大，别接劣质扩展坞） |
| 手环 | **先断开与手机的连接**——BLE 从机通常只允许一个主机连，手机连着板子就连不上 |
| 手环状态 | 戴在手腕上（不佩戴时多数手环不推心率数据） |

### 2.3 先确认串口能识别

```bash
pio device list        # PlatformIO
# 或看 Windows 设备管理器里的 COM 口
```

插上板子后应出现一个新串口。**没有新串口 = 线或驱动问题**，先解决它。

> 部分 ESP32-S3 板子用的是原生 USB（USB-Serial-JTAG），无需额外驱动；
> 若是 CH340/CP2102 则要装对应驱动。

## 三、配置（改 4 处，都在 `src/main.cpp` 顶部）

| 配置 | 填什么 | 注意 |
|---|---|---|
| `WIFI_SSID` / `WIFI_PASS` | 家里的 WiFi | **必须是 2.4GHz** —— ESP32 不支持 5GHz，这是最常见的"连不上"原因 |
| `API_BASE` | `http://139.129.108.119:8080`（线上） | 本地调试要填**电脑的局域网 IP**（如 `http://192.168.1.10:8080`），板子用不了 `127.0.0.1` |
| `BIND_CODE` | **App 生成的 6 位绑定码** | 见第 4 步；10 分钟有效，过期重新生成 |
| `DEVICE_SN` | 如 `HR-BRIDGE-001` | 同一块板子固定不变（重复烧写不变更，避免产生重复设备记录） |
| `BAND_NAME` | 手环广播名（如 `HR-287`） | **留空**则自动连接"第一个广播 0x180D 的设备"，更省事但可能连到别的设备 |

---

## 四、先取绑定码（关键顺序）

**必须在烧写/上电之前**，先在 App 里生成绑定码（只有 10 分钟有效）：

```
App → 我的 → 设备管理 → 选择数据归属成员（如"张三"）→ 点「生成绑定码」
→ 屏幕显示 6 位数字（如 263976）
```

然后把这个 6 位数字填进 `BIND_CODE`。**注意**：这个码决定了数据归属到哪个成员，
选错成员后面数据就记到别人名下（可在 App 里解绑后重新绑定，但会多一条设备记录）。

## 五、编译与烧写

### 5.1 先只编译（不烧写）

```bash
cd hardware/esp32_hr_bridge
pio run                 # 只编译
```

- **编译通过** → 进 5.2
- **编译失败** → 把完整报错发我（这一步预期可能需要 1~2 轮修正，因为固件未在本机验证过）

### 5.2 烧写

```bash
pio run -t upload       # 编译并烧写
pio device monitor      # 打开串口监视（115200）
```

Arduino IDE 则是：选好开发板与端口 → 点上传 → 打开串口监视器。

### 5.3 如果烧写卡住（板子一直在等）

ESP32-S3 多数支持自动下载，但个别板子需要手动进下载模式：
**按住 BOOT 键 → 点一下 RESET → 松开 BOOT**，再执行烧写。

## 六、上电后的验收（按顺序核对）

### 6.1 串口日志应依次出现

```
=== ESP32 手环心率桥接启动 ===
[API] 尚无设备令牌，将用绑定码换取
[WiFi] ✅ 已连接，IP 192.168.1.23
[API] ✅ 绑定成功，设备令牌已保存到 NVS
[API]    归属成员: 张三
[BLE] 开始扫描...
[BLE] 发现 HR-287  rssi=-58 [含心率服务]
[BLE] ✅ 已连接并订阅心率通知（请确保手环戴在手腕上）
[BLE] 心率 72 bpm
[API] ✅ 已上报心率 72 bpm
```

**看到最后两行 = 全链路通了。**

### 6.2 App 侧核对

| 位置 | 应该看到 |
|---|---|
| 我的 → 设备管理 | 出现一台设备：名称、**归属：张三**、**在线**、最近上报时间、固件 v2.0 |
| 健康 → 健康数据 | 出现心率记录，数值与串口一致，且带蓝色**「设备」**来源徽标 |

### 6.3 断网重连验证（可选但建议）

拔掉路由器电源 1 分钟再恢复：

- 串口应出现 `[WiFi] 连接失败` → 之后自动重连
- 期间心率读数进缓存，恢复后应出现 `[API] 补传缓存 N 条`
- App 里数据补齐

## 七、排查表

| 串口现象 | 原因 | 处理 |
|---|---|---|
| 没有串口 / 端口不出现 | 充电线或驱动问题 | 换数据线；装 CH340/CP2102 驱动 |
| `[WiFi] ❌ 连接失败` | 用了 5GHz；或密码错 | 换 2.4GHz；核对密码 |
| `[API] 绑定失败 HTTP 400` | 绑定码错/过期（仅 10 分钟） | 回 App 重新生成，改 `BIND_CODE` 重烧 |
| `[API] 绑定失败 HTTP 401` | 后端地址错或服务未启动 | 核对 `API_BASE` 与后端 `systemctl is-active health-app` |
| `[BLE] 未扫到任何设备` | 手环被手机 App 连着；或太远 | 断开手机蓝牙/手环 App；靠近到 1 米内 |
| `[BLE] 没找到目标手环` | `BAND_NAME` 与实际不符 | 看扫描日志打印的真实名字，照抄进配置 |
| `[BLE] 对方没有 0x180D` | 扫到的不是手环 | 填上 `BAND_NAME` 精确定位 |
| `[BLE] 已超过 10 秒没有心率数据` | 手环没戴 / 被别的主机占用 | 戴上；确认没被手机连着 |
| `[API] ❌ 上报失败 HTTP 401` | 设备被 App 解绑了 | App 重新生成绑定码 + 清 NVS（见下）重烧 |
| 上传成功但 App 看不到 | 看的是别的成员/时间范围 | 切到绑定时的成员；下拉刷新 |

**清 NVS（换账号、换成员、令牌失效时用）**：

```bash
pio run -t erase        # 擦除整片 Flash（含 NVS）
pio run -t upload       # 重新烧写
```

## 八、完工后的维护

| 场景 | 做法 |
|---|---|
| 换手环 | 只需改 `BAND_NAME` 重烧（令牌不变，App 里设备不用重绑） |
| 换 WiFi | 改 `WIFI_SSID/PASS` 重烧 |
| 换归属成员 | App 解绑 → 重新生成绑定码 → 改 `BIND_CODE` → 清 NVS → 重烧 |
| 固件升级 | 重烧即可；令牌存在 NVS，升级不丢 |
| 交给别人用 | App 解绑（令牌立即失效），对方重新绑定 |

## 十、两个可选增强（本次不做，列出备选）

1. **免重烧改配置**：把 WiFi 与绑定码改成 BLE 配网（手机连板子的 BLE 写参数），
   就不用每次改代码重烧。适合量产。
2. **本地队列持久化**：现在断网缓存放在内存（30 条环形），断电会丢；
   可改为写 NVS/Flash，保证一条不丢。
