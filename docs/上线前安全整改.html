上线前安全整改（R6）

本文列出必须在正式对外前处理的安全问题，按风险排序。

每项都给出可直接执行的步骤；涉及生产配置的改动必须安排维护窗口，

因为配置与环境变量不同步会导致服务起不来。

1. 注册验证码完全不校验（最高风险）🔴

现状：UserServiceImpl 直接跳过短信校验，且系统里没有发码接口。 结果是任何人可以用任意 6 位数字注册任意手机号，包括别人的号码。

两种处理方式，需二选一（这是产品决策，不是技术问题）：

方案做法影响
A. 接入真实短信接入阿里云短信，sendCode 真实下发、register 校验并做频率限制（同号 60s 一次、每日上限）需要你的阿里云短信签名与模板；有短信费用
B. 明确免验证去掉注册页的验证码输入框，后端文档写明"当前为免验证注册"零成本但任何人可注册任意号码，仅适合内测

在做出选择之前，建议先限制注册入口（例如仅内网可访问注册接口）， 避免内测期内被批量注册。

2. 明文凭据已进入 Git 仓库 🔴

现状（git ls-files 可查）：

文件泄露内容
spring-boot-backend/src/main/resources/application-prod.yml数据库口令、JWT 密钥
spring-boot-backend/src/main/resources/application.ymlJWT 密钥等
deploy/server/application-prod.yml数据库口令
flutter-app/android/app/keystore.propertiesAndroid 签名密钥口令（泄露后可被人重签名冒充 App）
多个 docs/*.md同上（已打码，见本次提交）

整改步骤（需维护窗口）：

# 1) 服务器上先设置环境变量（写入 /etc/health-center.env，权限 600）
cat > /etc/health-center.env <<'EOF'
DB_PASSWORD=<真实口令>
JWT_SECRET=<新的强随机串>
EOF
chmod 600 /etc/health-center.env

# 2) systemd 单元里引用它
#    /etc/systemd/system/health-app.service 增加：
#    EnvironmentFile=/etc/health-center.env

# 3) 配置文件改为占位符（不写真实值）
#    spring.datasource.password: ${DB_PASSWORD}
#    jwt.secret: ${JWT_SECRET}

# 4) 重启并验证
systemctl daemon-reload && systemctl restart health-app
curl -s localhost:8080/api/auth/login -H 'Content-Type: application/json' \
     -d '{"phone":"13800138000","password":"123456"}' | head -c 200

# 5) 清理 git 历史（会被重写的提交，需团队知会）
#    git filter-repo --path <涉密文件> --invert-paths
#    然后强推；所有协作者需重新克隆

注意：口令一旦进过仓库就应视为已泄露 —— 即使清理了历史， 也必须更换数据库口令与 JWT 密钥（第 1 步里的 <真实口令> 要用新值）。

3. 数据库排序规则不一致 🟡

现状：user 表是 utf8mb4_0900_ai_ci，其余 6 张表是 utf8mb4_unicode_ci。 两表 JOIN 比较字符串时可能报 Illegal mix of collations。

整改步骤（低峰期执行，先备份）：

-- 备份
CREATE TABLE user_bak_collation AS SELECT * FROM user;

-- 统一（会重建表，期间该表短暂锁写）
ALTER TABLE `user` CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 校验
SELECT TABLE_NAME, TABLE_COLLATION FROM information_schema.TABLES
 WHERE TABLE_SCHEMA='health_center_db' ORDER BY TABLE_NAME;

4. 设备令牌（已完成，无需整改）✅

设备接入已按最小权限实现：令牌只存 SHA-256 哈希、只能写健康数据、 App 可随时解绑使其立即失效。固件里不再保存 App 账号口令（v2 已改）。

5. 其它建议 🟢

  • scripts/dbviewer 用的是只读账号 ✅（已确认 README 里也是只读连接），

但口令仍应从环境变量读，不要写在代码/文档里

  • 生产 CORS 应显式限定域名，不要用 *
  • 建议给 /api/auth/** 加登录失败频率限制（防暴力破解）

优先级建议

顺序项理由
1注册验证码（方案 A/B 二选一）直接影响真实用户账号安全
2更换数据库口令与 JWT 密钥 + 环境变量化凭据已泄露，越早换越好
3Android 签名口令外置影响 App 分发可信度
4排序规则统一隐患，低峰期做即可
