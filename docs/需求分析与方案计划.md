### 1.2 需求的本质归纳

散落的诉求其实收敛为三件事：

1. **数据来源自动化**（R1 拍照、R2 手环）—— 减少手工录入，这是产品的核心价值
2. **数据可信与安全**（R6、R8）—— 上线前提
3. **可交付与可维护**（R7）—— 让后续接手的人能改、能验

## 二、方案设计

### 2.1 R2：设备接入体系（本次重点）

**问题**：现有固件用"账号+口令登录"向后端写数据。板子一旦被拆开，账号口令就泄露，
且令牌权限过大（能改资料、能看全家数据）。不适合量产。

**方案：一次性绑定码 → 设备令牌（最小权限）**

```mermaid
flowchart LR
    A[App 生成绑定码<br/>6 位数字 · 10 分钟有效] --> B[板子 POST /api/device/bind<br/>code + 设备序列号]
    B --> C[后端校验绑定码<br/>签发 deviceToken<br/>仅允许写健康数据]
    C --> D[板子存 NVS]
    D --> E[周期上报<br/>POST /api/device/health-data<br/>X-Device-Token]
    E --> F[health_data 表<br/>data_source=device]
    F --> G[App 显示 + 预警规则生效]
```

**接口设计**

| 接口 | 鉴权 | 说明 |
|---|---|---|
| `POST /api/device/bind` | 绑定码 | 入参 `bindCode`、`deviceSn`、`deviceName`；返回 `deviceToken`、`memberId` |
| `POST /api/device/health-data` | 设备令牌 | 入参 `dataType`、`value1`、`value2`、`measureTime`；**只能写**，不能读 |
| `POST /api/device/heartbeat` | 设备令牌 | 上报在线状态、信号强度、电池（用于 App 显示设备是否在线） |
| `GET/DELETE /api/device` | 用户 JWT | App 查已绑定设备 / 解绑（解绑即令牌失效） |
| `POST /api/device/bind-code` | 用户 JWT | App 生成绑定码（绑定到指定成员） |

**数据模型**

```
device
  id, user_id, member_id, device_sn(唯一), device_name, device_type
  token_hash          -- 只存哈希，防拖库
  bind_code, bind_code_expire
  last_seen, status, firmware_version, created_at
```

`health_data` 已有 `data_source` 字段：设备写入时置 `device`，并可选加 `device_id`。

**App 侧**

- 我的 →「设备管理」：生成绑定码（大字 + 二维码）、已绑定设备列表（在线状态 / 最近上报时间 / 解绑）
- 健康数据列表：设备来源的记录加"设备"标签，与手工录入区分

**固件侧（v2）**

- 首次上电：BLE 配网（或过渡期保留硬编码 WiFi）+ 输入绑定码 → 换令牌 → 存 NVS
- 上报改用 `X-Device-Token`，不再使用账号口令
- 断网缓存持久化到 NVS（现在只在内存，断电即丢）

### 2.2 R1：识别准确率与真机验证

**现状**：链路正确（用仓库已有模型），但准确率与泛化都有缺口。

| 步骤 | 做法 | 预期 |
|---|---|---|
| 真机验证 | 装新 APK（已构建），读 App 日志确认走新链路 | 确认端侧可用 |
| 提准确率 | 用 60 张真实照片 + **真实退化增强**（±8° 旋转、缩放、亮度/对比、模拟反光与模糊、JPEG）微调 `bpressure_multihead.tflite` | 目标 ≥85% |
| 诚实评估 | 45 张微调 / **15 张只做验证**；报告验证集数字而非全量 | 结论可信 |
| 泛化验证 | 需要**不同机型**的新照片（你手边若有别的血压计，拍 10~20 张价值远大于同机型再拍 100 张） | 才知道能否推广 |

### 2.3 R6：上线前安全（必须做，含一个需你决策的点）

| 项 | 方案 | 决策点 |
|---|---|---|
| 注册验证码 | A. 接入短信服务（需阿里云短信密钥与签名）<br/>B. 明确改为免验证注册，去掉验证码输入框，避免误导用户 | **需要你选 A 或 B** |
| 凭据清理 | 从代码、README、systemd 单元中移除明文口令/密钥，改读环境变量；清理 git 历史 | 需确认是否接受改写历史 |

### 2.4 R8：数据资产

60 张真实照片 + 标注是**唯一且不可再生的**（原始 12MP，336 MB），必须入库：

- 方案 A：**Git LFS**（原图无损，仓库不膨胀）—— 推荐
- 方案 B：压缩入库（长边 1600 + JPEG 85，约 20 MB，损失原图精度，影响后续定位训练）
- 方案 C：只入库标注 + 清单 + 校验和（照片仍留本地，接受风险）

## 三、分阶段计划

**P0 完成即达成**：心率数据从手环到 App 全自动，不依赖手机常开、不把账号口令放进硬件。

3. 把基准脚本（`eval_lcd_detector.py` / `eval_multihead.py` / `e2e_pipeline.py`）写成一条命令的回归

**验收**：holdout 上三项全对 ≥85%；回归脚本可一键复现。

### P2 · 上线前安全（预计 1 天，含你的决策）

### P4 · 完整性与体验（可选，按需排）

## 四、风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| 手环**只允许一个主机连接** | 板子连着时 App 连不上手环 | 采集固定交给板子，App 只读服务器数据（当前方案已规避） |
| ESP32 **仅支持 2.4GHz WiFi** | 家里若只有 5GHz 连不上 | 固件说明已标注；必要时加 BLE 配网提示 |
| 设备令牌泄露 | 他人可伪造健康数据 | 令牌只存哈希、仅允许写、App 可随时解绑 |
| 模型**过拟合这 60 张** | 换机型准确率骤降 | 引入不同机型的少量新照片做验证；增强训练 |
| 手机 USB 授权 | OCR 真机验证与部分联调阻塞 | 一次性人工确认 |
| 数据只在本机 | 换设备即丢失 60 张原始数据 | P3 入库（建议 LFS） |

## 五、建议的执行顺序

```
P0 设备接入  ──►  P1 OCR 收尾  ──►  P2 安全  ──►  P3 资产与文档  ──►  P4 体验
   (1.5天)          (1天)            (1天)          (0.5天)          按需
```

理由：P0 是当前唯一"新增能力"且能立刻产生用户价值（心率自动入库）；
P1 是把已有成果做扎实（避免"看起来 71.7% 实际不能推广"）；
P2 是上线前提（其中验证码一项需要你决策）；P3 是防资产丢失。

| 预警去重（P0-1，本轮改动引入的缺陷） | ✅ 完成，单测 7/7、冒烟 7 次超标→1 条 |

设计要点与证据见 `docs/交接说明.md` 第二节与第八节。**最关键的一点**：
`/api/device/latest` 原本查库里"最新一条"，只做节流会让监控页滞后 60 秒；
因此上报时同步刷新内存实时值（`REALTIME`），`listLatest` 优先取缓存，
节流只作用于历史入库。

**真机验收（2026-10-16，实测非推断）**：轮询实测 3.00 秒 / 数字在跳（94→102→103）/
曲线在长（3→7→12 点）/ 状态「已连接」/ **摘下手环 26 秒后自动变「数据已停止」+ `--`** /
退后台 13 秒 0 请求 / 回前台立刻刷新 / 离开页面 0 请求 / 两个入口都能进 /
未绑定时给出「还没有可监控的设备」+ 跳转。
过程中发现并修掉一个**只有真机才暴露的崩溃**：监控页 `_timer` 写成 `late final`，
退后台再回前台会第二次赋值抛 `LateInitializationError`（`analyze` 与编译都不报），
并泄漏一个永不被 cancel 的 3 秒定时器（修复前离开页面后 15 秒仍有 7 次请求，修复后 0 次）。

**没有硬件也能验**：`spring-boot-backend/src/test/sim-board.ps1` 扮演板子
（每 5 秒上报 + 心跳 + 设备令牌），除固件本身外整条链路都能脱离硬件复验。

后端接口（已冒烟验证）：

    POST /api/device/bind-code      App 生成 6 位绑定码（10 分钟有效）
    POST /api/device/bind           设备用绑定码换令牌
    POST /api/device/health-data    设备上报（X-Device-Token）
    POST /api/device/heartbeat      设备心跳
    GET  /api/device                App 查看设备（含在线状态）
    DELETE /api/device/{id}         App 解绑（令牌立即失效）
