# 血压计 LCD 视觉识别——经验总结

## 1. 项目背景

- **目标**：从血压计照片中自动识别 LCD 屏幕上的血压数值（收缩压、舒张压、脉搏）
- **技术路线**：LCD 区域检测 → 裁剪 → TFLite 数字识别 → 解析血压值
- **数据集**：63 张标注照片（血压计 LCD 区域框标注），图片文件名格式为 `收缩压-舒张压-脉搏.jpg/png`

## 2. 数据集分析发现

### 2.1 尺寸分布

63 张图片共包含 **8 种不同分辨率**，主要集中在以下三种：

| 分辨率 | 数量 | 占比 |
|--------|------|------|
| 1279×1706 | 最多 | 主要 |
| 3060×4080 | 较多 | 主要 |
| 3072×4096 | 较多 | 主要 |

其余 5 种分辨率各有少量样本。

### 2.2 LCD 位置变化

- **相对 X 范围**：0.00 ~ 0.87（LCD 可能出现在画面最左到最右）
- **相对 Y 范围**：0.22 ~ 0.73（LCD 可能出现在画面上方到下方）
- **核心发现**：相同分辨率组内 LCD 位置标准差仍很大，例如 3072×4096 组的 RX 标准差为 0.245

### 2.3 LCD 宽高比变化

- **宽高比范围**：0.17 ~ 3.93
- 横拍、竖拍、俯拍、仰拍角度差异极大，导致同一台血压计的 LCD 在不同照片中呈现完全不同的形状

### 2.4 核心结论

> **拍摄角度不固定时，无法用简单的启发式规则（如中心位置、固定比例）定位 LCD。** 必须使用数据驱动的检测方法。

## 3. 方案探索与对比

| 方案 | 准确率 | 速度 | 结论 |
|------|--------|------|------|
| 启发式检测（中心/对比度假设） | 0% | 快 | 失败 |
| 单模板匹配 | 0% | 中 | 失败 |
| 多模板匹配（留一法） | 47% | 98分钟/63张 | 太慢不可用 |
| TFLite 置信度选择最佳裁剪 | 31.7% | 中 | 模型对错误裁剪也自信 |
| 血压合理性评分选择 | 31.7% | 中 | 多个裁剪都产出合理值，无法区分 |
| 整张照片直接输入 TFLite | 0% | 快 | 模型训练时用的是裁剪图 |
| YOLOv8n 检测 + TFLite 识别 | 59% | 3秒/63张 | 最可行的自动方案 |
| 人工标注裁剪 + TFLite | 94.4% | 快 | 理论上限 |

### 各方案简要说明

#### 3.1 启发式检测（中心/对比度假设）

假设 LCD 位于图片中心区域或具有最高对比度。结果：**准确率 0%**。因为实际照片中 LCD 位置极其分散（X 范围 0~0.87），对比度也因环境光而异，没有任何启发式规则能覆盖所有情况。

#### 3.2 单模板匹配

选取一张图片作为模板，用 OpenCV 模板匹配查找其他图片中的 LCD 区域。结果：**准确率 0%**。不同图片的分辨率、角度、缩放差异太大，单模板无法泛化。

#### 3.3 多模板匹配（留一法）

对每张图片，用其余 62 张作为模板进行匹配，取最佳结果。结果：**准确率 47%**，但耗时 98 分钟处理 63 张图片。虽然准确率尚可，但速度完全不可接受。

#### 3.4 TFLite 置信度选择最佳裁剪

对同一张图片尝试多种裁剪方案，选择 TFLite 模型输出置信度最高的裁剪。结果：**准确率 31.7%**。关键问题是模型对错误裁剪区域也会给出高置信度，导致"自信地错误"。

#### 3.5 血压合理性评分选择

对多种裁剪方案的识别结果进行血压合理性评分（收缩压 70~200，舒张压 40~150 等）。结果：**准确率 31.7%**。因为多个不同裁剪方案都可能产出"合理"的血压值，无法通过合理性判断哪个裁剪是正确的。

#### 3.6 整张照片直接输入 TFLite

不裁剪，直接将整张照片缩放到 224×224 输入 TFLite 模型。结果：**准确率 0%**。模型训练时用的是手动裁剪的 LCD 区域图，输入分布完全不同。

#### 3.7 YOLOv8n 检测 + TFLite 识别

用 YOLOv8n 检测 LCD 区域，裁剪后输入 TFLite 识别。结果：**准确率 59%**，处理 63 张图片仅需 3 秒。这是目前最可行的自动方案，但仍有较大提升空间。

#### 3.8 人工标注裁剪 + TFLite

人工标注 LCD 区域后裁剪，再输入 TFLite 识别。结果：**准确率 94.4%（54/57）**。这是系统的理论上限，说明 TFLite 识别模型本身已经足够好，瓶颈在于自动检测环节。

## 4. TFLite 数字识别模型经验

### 4.1 模型架构

- **类型**：Multi-head CNN（多分类头 CNN）
- **输入**：224×224 RGB 图像，归一化到 [0, 1]
- **输出**：7 个独立分类头，每个头输出 0-9 数字分类概率

### 4.2 输出头映射

| 血压字段 | 位数 | 对应输出头 |
|----------|------|-----------|
| 收缩压（SYS） | 3 位 | 头4、头1、头5 |
| 舒张压（DIA） | 2 位 | 头3、头0 |
| 脉搏（PULSE） | 2 位 | 头2、头6 |

### 4.3 训练数据与性能

- **训练数据**：`lcd_crops/` 目录下的 57 张手动裁剪的 LCD 图片
- **在裁剪图上的准确率**：94.4%（54/57）
- **平均绝对误差（MAE）**：
  - 收缩压：0.9 mmHg
  - 舒张压：4.3 mmHg
  - 脉搏：0.0 bpm

### 4.4 关键发现

> **模型对裁剪区域的数字非常敏感，输入必须包含 LCD 且不能有太多背景干扰。** 输入分布的一致性是使用 TFLite 模型的首要原则——推理时的输入必须与训练时的输入尽可能一致。

## 5. YOLO 目标检测经验

### 5.1 训练配置

- **模型**：YOLOv8n（nano），使用预训练权重迁移学习
- **数据**：63 张标注数据，80/20 划分训练/验证集
- **标注格式**：JSON 标注转换为 YOLO 格式（class x_center y_center width height，归一化坐标）

### 5.2 训练结果

| 指标 | 值 |
|------|-----|
| mAP50 | 0.596 |
| Precision | 0.775 |
| Recall | 0.462 |

### 5.3 检测效果

- **IoU >= 0.5** 的图片占比：87%
- **IoU >= 0.25** 的图片占比：90%
- **漏检主要场景**：极端角度（横拍、侧拍）和小尺寸图片

### 5.4 关键发现

> **当 YOLO 检测框 IoU >= 0.8 时，端到端准确率可达 89%。** 端到端 59% vs 理论上限 94.4% 的差距主要来自检测框不够精确。提升检测框质量比提升识别模型更重要。

## 6. 踩过的坑

### 6.1 模型输入分布一致性

TFLite 模型训练时使用的是手动裁剪的 LCD 图片（仅包含 LCD 区域），推理时必须先将图片裁剪到 LCD 区域再输入。如果直接将整张照片缩放到 224×224 输入，**准确率为 0%**。

### 6.2 Windows 编码问题

Python 在 Windows 上默认使用 GBK 编码，打印包含 emoji 字符的字符串时会抛出 `UnicodeEncodeError`。解决方案：
```python
import sys
sys.stdout.reconfigure(encoding='utf-8')
```

### 6.3 pip SSL 问题

本地网络存在 SSL 代理，`pip install` 会报 `check_hostname requires server_hostname` 错误。解决方案：
```bash
pip install <package> --trusted-host pypi.org --trusted-host pypi.python.org --trusted-host files.pythonhosted.org
```

### 6.4 TensorFlow Lite API 废弃

`tf.lite.Interpreter` 已被标记为废弃，未来将迁移到 `ai_edge_litert` 包。建议在代码中做好兼容处理。

### 6.5 ONNX2TF 依赖复杂

将 YOLO 模型从 ONNX 转换为 TFLite 时，需要特定版本的依赖组合：
- `onnx_graphsurgeon`
- `sng4onnx`
- `onnxslim`
版本不匹配会导致转换失败。

### 6.6 TFLite 输出格式

YOLOv8 导出的 TFLite 模型输出格式可能是 `(1, 5, 8400)` 或 `(1, 8400, 5)`，分别对应 NCHW 和 NHWC 布局。使用前必须确认格式，否则 NMS 后处理会出错。

### 6.7 图像预处理差异

Python PIL 和 Dart `image/image` 包在像素读取、颜色空间（RGB vs BGR）、归一化方式上可能有差异。Flutter 端集成时需要严格对齐预处理逻辑。

## 7. IoU 与识别准确率的关系

| IoU 区间 | 识别准确率 | 说明 |
|----------|-----------|------|
| IoU >= 0.8 | 89% | 检测框与人工标注高度吻合 |
| 0.5 <= IoU < 0.8 | 33% | 检测框偏差导致裁剪包含过多干扰 |
| IoU < 0.5 | 0% | 检测框严重偏离，无法识别 |

### 结论

> **检测框精度是端到端系统的瓶颈。提升 YOLO 的 IoU 比提升 TFLite 识别能力更重要。** 当前 TFLite 模型在人工裁剪图上已达 94.4% 准确率，而端到端仅 59%，中间 35 个百分点的差距几乎全部来自检测环节。

## 8. 可复用的开发模式

### 8.1 先验证数据再动手

在尝试任何算法之前，先对数据集进行统计分析——了解位置分布、尺寸变化、角度差异等。本项目中，数据分析直接证明了"无法用启发式规则定位 LCD"，避免了在错误方向上浪费时间。

### 8.2 留一法交叉验证

小数据集（63 张）场景下，留一法（leave-one-out）能充分利用有限数据验证算法泛化能力。多模板匹配方案就是通过留一法验证的。

### 8.3 端到端验证

每个环节（检测 → 裁剪 → 识别）都要串联起来测试，不能只看单环节指标。YOLO 的 mAP50=0.596 看起来不错，但端到端准确率只有 59%，两者并不等价。

### 8.4 可视化调试

在图片上画出检测框（Ground Truth vs 预测），直观对比差异。本项目通过可视化快速定位了漏检和框偏移问题。

### 8.5 对照实验

保持其他条件不变，只改变一个变量来验证影响。例如：保持 TFLite 模型不变，只改变裁剪区域大小，观察准确率变化。

## 9. 后续改进方向

### 9.1 扩充数据集（优先级：高）

增加标注数据到 200+ 张，覆盖更多拍摄角度、光线条件和血压计型号。当前 63 张数据量偏小，是制约 YOLO 检测精度的根本原因。

### 9.2 YOLO 检测框后处理（优先级：高）

根据 LCD 屏幕的物理长宽比对检测框进行约束调整，去除明显不合理的检测框。

### 9.3 多框融合策略（优先级：中）

对 YOLO 输出的多个候选框分别进行 TFLite 识别，选出最合理的结果。可以结合血压合理性评分、置信度等多维度指标。

### 9.4 TFLite 模型微调（优先级：中）

用 YOLO 自动裁剪的 LCD 图片（而非人工裁剪图）重新训练 TFLite 模型，让它适应真实检测框带来的噪声和偏差。

### 9.5 端到端方案（长期方向）

考虑使用端到端目标检测 + OCR 方案（如 PaddleOCR）替代当前的两阶段方案（检测 → 裁剪 → 识别），减少中间环节的误差累积。
