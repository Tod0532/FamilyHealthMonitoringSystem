# ESP32-S3 手环心率桥接固件

用手环（BLE）采心率 → 板子（ESP32-S3）→ WiFi 上报 → 家庭健康中心后端 → App 显示/预警。

**前提已确认**：用 nRF Connect 已验证手环能连接并读到标准心率服务
`0x180D` 上的心率（`0x2A37`），因此本固件按标准协议实现，不依赖厂商私有协议。

---

## 为什么让板子当主机

BLE 从机（手环）通常**只允许一个主机连接**：手机连上了，板子就连不上，反之亦然。
让板子常连手环、手机只负责看数据，就不会互相抢连接，而且板子可以 7×24 采集。

```
手环 ──BLE 通知(0x2A37)──> ESP32-S3 ──WiFi/HTTP──> 后端 ──> App
```

## 链路特点

- **不需要改后端**：直接复用现有接口
  1. `POST /api/auth/login {phone,password}` → 取 `data.accessToken`
  2. `POST /api/health-data {memberId,dataType:"heart_rate",value1:心率,...}` 带 `Bearer` 令牌
- token 过期（默认 2 小时）自动重新登录
- **断网缓存**：离线时读数进 30 条环形缓冲，恢复联网后自动补传
- BLE 掉线自动重连；手环长时间无数据会打印提示（通常是没戴在手上或被子App占用）
- 上报节流：心率变化 ≥3 bpm 即报，否则每 60 秒报一次（避免刷爆数据库）

## 烧写

```bash
cd hardware/esp32_hr_bridge
pio run -t upload          # 编译并烧写
pio device monitor         # 看串口日志（115200）
```

没有 PlatformIO 也可用 Arduino IDE：装好 ESP32 开发板支持 +
`NimBLE-Arduino`、`ArduinoJson` 两个库，板子选 `ESP32S3 Dev Module`。

## 配置（全在 `src/main.cpp` 顶部）

| 项 | 说明 |
|---|---|
| `WIFI_SSID` / `WIFI_PASS` | 板子连的 WiFi（**注意：ESP32 只支持 2.4GHz**，5GHz 连不上） |
| `API_BASE` | 后端地址。线上 `http://139.129.108.119:8080`；本地调试要填**电脑的局域网 IP**（板子无法用 `127.0.0.1`） |
| `BIND_CODE` | **App 生成的 6 位绑定码**（我的 → 设备管理 → 生成）。首次上电用它换设备令牌，令牌存 NVS，之后不再需要 |
| `DEVICE_SN` | 设备序列号，同一块板子固定填一个即可 |
| `BAND_NAME` | 手环广播名（nRF Connect 里看到的那个）。**留空**则自动连接"第一个广播 0x180D 的设备" |

## 排查

| 现象 | 原因 / 处理 |
|---|---|
| `未扫到任何设备` | 手环没在广播（可能被手机 App 连着，先断开）；或离得太远 |
| `没找到目标手环` | `BAND_NAME` 与实际不符。看扫描日志里打印的真实名字再填 |
| `对方没有 0x180D` | 扫到的不是手环。填上 `BAND_NAME` 精确定位 |
| `已超过 10 秒没有心率数据` | 手环没戴在手腕上；或被别的主机占用连接 |
| `WiFi 连接失败` | 用了 5GHz 频段（ESP32 不支持）；或密码错 |
| `绑定失败 HTTP 400` | 绑定码错或已过期（只有 10 分钟），去 App 重新生成一个 |
| `上报失败 HTTP 401` | 设备被 App 解绑了；清掉 NVS 重新绑定 |
| 数据上传成功但 App 看不到 | App 是按成员/时间筛选的，确认看的是同一位成员 |

## 安全模型（v2 已实现）

不再把 App 账号口令写进固件。流程：

```
App「我的 → 设备管理」生成 6 位绑定码（10 分钟有效）
  → 板子首次上电 POST /api/device/bind 换取设备令牌（存 NVS）
  → 之后只用 X-Device-Token 上报，令牌只能写健康数据
  → App 可随时解绑，令牌立即失效
```

## 后续可改进

2. **本地上报队列持久化**：现在是内存环形缓冲，断电会丢；可写进 NVS/Flash。
3. **上传血氧**：部分手环的健康服务里还有血氧/步数特征，可按同样方式订阅。
4. **配网**：现在 SSID/密码是硬编码；量产建议用 BLE 配网或 SmartConfig。
